# RC21 Stage 8: Campaign, report, ranking, and resume integration

Stage 8 adds immutable runtime-contract evidence without changing task scorers, score formulas, canonical historical rows, or ranking update controls. `RuntimeIdentity` is schema version 1, deterministic, immutable, JSON-safe, and SHA-256 hashed from compatibility-relevant fields only. It records backend/adapter, credential-free normalized endpoint, selected profile/provenance, server version, model artifact evidence, canonical NVIDIA UUIDs, runtime-significant order, and explicit context/batch/KV/parallel/spill/offload/split settings. Unknown values remain unknown.

Plans can freeze complete benchmark identities and an independent judge identity state. Compatibility is fail-closed for backend, endpoint/profile, server, model, UUID/order, execution, or schema changes; timestamps do not affect it. Legacy plans and rows remain readable and reportable as legacy/unknown, but an unsafe legacy resume must create a new campaign rather than adopt current-host assumptions.

New rows reference one run-level `runtime_identity.json` via schema version, full hash, and runtime variant ID. Reports retain variant-distinct duplicate cells and expose additive metadata without treating telemetry as placement proof or fit as a scoring input. Ranking raw evidence can retain variants; canonical score behavior is preserved and no report mutates ranking stores.
