# RC21 Stage 8 integration audit and plan

The campaign immutable boundary is `campaigns/<id>/plan/plan.json`, written atomically by `campaign.write_campaign_plan`; its existing equivalence comparison ignores only `created_at`. Primary runner evidence is `raw_results.jsonl`, with per-model digest metadata in `model_identities.json`; reports deduplicate model/task/task-hash cells and rankings select one `(model_digest_resolved, task)` row. These historical fields remain readable and retain their score semantics.

Stage 8 adds a schema-versioned frozen runtime identity as additive evidence. It distinguishes backend/adapter, credential-free endpoint, selected profile, observed server version, backend model/artifact identity, canonical physical UUIDs, runtime-significant device order, and explicit execution settings. PCI only corroborates UUIDs. Index and CUDA ordinal are rejected as durable physical identity. The hash covers canonical compatibility fields, not timestamps, display-only evidence, PCI text, or observation order.

New campaign plans may carry `runtime_identities` and separate judge identity state; legacy plans remain readable but resume must fail closed when an identity cannot be reconstructed from persisted evidence. New runner rows reference a run-level `runtime_identity.json` with full hash and variant ID. Report deduplication includes the variant, so separate runtime evidence is not discarded. Canonical ranking aggregation remains intentionally unchanged in this bounded implementation; Stage 8 introduces variant metadata without using it as a score input or automatic ranking-store mutation.

External llama.cpp remains one served model per selected endpoint. No switching, server launch, lifecycle action, or judge fallback is introduced. Missing judge identity is explicit (`judge_not_required` in a frozen plan); separate judge execution remains an external, profile-selected boundary.

## Report-provenance correction

The report aggregation path was audited with mixed current and legacy rows. The defect was presentation-only: a legacy model could correctly retain `legacy_unknown` row state while also showing the run-level identity artifact for a different current model. The report now attaches that artifact only where a row in the model aggregate references its full identity hash. `summary_meta.json` adds an explicitly run-level `runtime_provenance` section, while `summary.json` remains model-scoped and includes variant summaries. `scorecard.csv` adds deterministic provenance columns without changing pre-existing columns or score values. This is additive evidence; it neither changes canonical weights nor mutates ranking stores.
